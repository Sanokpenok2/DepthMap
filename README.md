# Карта глубины по стереопаре

Программа на Python строит карту глубины (диспарности) на основе двух
изображений стереопары — левого и правого. Используется алгоритм
Semi-Global Block Matching (SGBM) или классический Block Matching (BM)
из OpenCV, с опциональной пост-обработкой WLS-фильтром.

## Установка

```bash
pip install -r requirements.txt
```

## Веб-интерфейс

Простой GUI с загрузкой левого/правого фото и настройкой параметров:

```bash
python app.py
```

Откроется браузер на `http://127.0.0.1:7860`. Загрузите стереопару,
при необходимости файл `.npz` от калибровки и нажмите «Построить».
Клик по карте диспаритета показывает расстояние (нужна калибровка или focal/baseline).

## Трекинг объекта по стерео-видео

Скрипт `video_track_depth.py` принимает либо **одно SBS-видео** (кадр
пополам: L|R), либо **два отдельных** файла левой и правой камеры. Даёт
выбрать объект на левом кадре, сопровождает его трекером и считает расстояние
по медиане диспаритета внутри ROI.

```bash
python video_track_depth.py ^
    --video stereo_sbs.mp4 ^
    --calib stereo_calib.npz
```

```bash
python video_track_depth.py ^
    --left-video left.mp4 --right-video right.mp4 ^
    --calib stereo_calib.npz
```

Полезно для ускорения:

```bash
python video_track_depth.py ^
    --video stereo_sbs.mp4 ^
    --calib stereo_calib.npz ^
    --sgbm-interval 3 --tracker kcf --smooth 5 ^
    --threads 0 --workers 2 --async-sgbm
```

| Параметр | Описание | По умолчанию |
|---|---|---|
| `--video` | SBS-файл (левая половина — левая камера) | — |
| `--left-video` / `--right-video` | Пара отдельных видео вместо `--video` | — |
| `--swap-lr` | Поменять L/R местами (половины или потоки) | выкл. |
| `--calib` | Калибровка `.npz` (обязательна, кроме `--track-only`) | — |
| `--auto-disparity` / `--no-auto-disparity` | Подстраивать диапазон диспаритета при приближении объекта | вкл. |
| `--z-near` / `--z-far` | Диапазон сцены, м (для 1000+ м: ~200 / 2500) | `200` / `2500` |
| `--long-range` / `--no-long-range` | Жёсткий потолок SGBM + без расширения к ближней зоне | вкл. |
| `--tracker` | База гибрида: `csrt` / `kcf` / `mosse` / `ncc` (+ CLAHE-NCC) | `kcf` |
| `--kornia-tracker` / `--no-kornia-tracker` | Базовый трек как в DepthMapKornia (NCC template вместо KCF) | выкл. |
| `--roi-smooth` | Сглаживание рамки `[0..1)`: больше = плавнее (больше лаг) | `0` |
| `--lock-size` / `--no-lock-size` | Фиксировать размер. Выкл. — scale по NCC (приближение/удаление) | выкл. |
| `--verify-threshold` | Мин. CLAHE-NCC; ниже soft-полосы копим LOST | `0.30` |
| `--max-jump` | Макс. прыжок по X (доли ширины ROI; для быстрых L→R ≥3) | `4.0` |
| `--lost-patience` | Плохих кадров подряд до LOST | `14` |
| `--reacquire` / `--no-reacquire` | Повторный захват после потери | вкл. |
| `--reacquire-threshold` | Порог NCC для перезахвата (выше = меньше ложных прыжков) | `0.55` |
| `--reacquire-radius` | Окно поиска (доли размера ROI) | `3.5` |
| `--reacquire-interval` | Поиск при LOST каждые N кадров | `2` |
| `--reacquire-scale-min` / `--max` | Масштабы при поиске (удаление…приближение) | `0.50` / `2.0` |
| `--click-tolerance` | Допуск яркости при выборе кликом (C); в окне `+/-` | `12` |
| `--keep-aspect`, `--max-scale-step`, `--max-size-ratio`, `--verify-rel`, `--min-iou`, `--reacquire-global`, `--no-grabcut` | Legacy CLI (принимаются, почти не влияют) | — |
| `--sgbm-interval` | Считать карту глубины каждые N кадров | `2` |
| `--smooth` | Окно медианы по измерениям (кадры) | `21` |
| `--smooth-max-ratio` | Отсев скачков Z/disp сильнее чем в N раз | `2.0` |
| `--smooth-ema` | EMA после медианы `[0..1]` (меньше = плавнее) | `0.2` |
| `--smooth-disp-jump` | Макс. скачок диспаритета (px) без отбраковки | `1.5` |
| `--clahe` / `--no-clahe` | CLAHE на gray (важно для низкоконтрастного ТВ/ИК) | вкл. |
| `--roi-inset` | Обрезка краёв ROI при измерении дистанции `[0..0.45)` | `0.32` |
| `--surface` | `far` / `near` / `median` — поверхность в ROI | `median` |
| `--threads` | Потоки OpenCV для SGBM/remap (`0` = все ядра) | `0` |
| `--workers` | Параллельная подготовка L/R кадров | `2` |
| `--async-sgbm` / `--no-async-sgbm` | SGBM в фоне, трекинг не ждёт | вкл. |
| `--debug-disparity` / `--no-debug-disparity` | Окно L\|R: пиксели ROI и соответствия `x-d` (клавиша **D**) | выкл. |
| `--track-only` | Только захват и трекинг, без SGBM и расстояния (калибровка не нужна) | выкл. |
| `--max-fps` | Ограничить скорость обработки (кадр/с); `0` = без лимита | `0` |
| `--output` | Сохранить видео с оверлеем | — |

Управление в окне: **Space** — пауза, **R** — рамка, **C** — клик, **D** — отладка диспаритета (L↔R), **Q** — выход. Объект можно не выбирать на старте — видео проигрывается, а трекинг начинается после первого выбора.

**Защита от дрейфа (thermal IR 640×512).** Гибрид: KCF на CLAHE-кадре →
**CLAHE-NCC** (центр + масштаб) + **mean-intensity** gate (не цеплять холодный
фон). Низкий score → fail-streak → hold/chase → LOST. Reacquire — локальный
`matchTemplate` с тройным фильтром (NCC ≥ порога, peak_ratio, |ΔI|), без прыжка
на непохожие объекты.

**Выбор кликом (C).** FloodFill по яркости + барьер Canny (удобно для gray/ИК).
В окне выбора: **`+/-`** — допуск. `--click-tolerance`, `--no-grabcut` сохранены
для совместимости (GrabCut в новом трекере не используется).

### Изолированный модуль трекинга

Логика в `object_tracker.py`: **KCF + CLAHE-NCC + intensity + строгий reacquire**.
Не зависит от стерео — можно тестировать на одном видео:

```bash
python object_tracker.py --video left.mp4 --tracker kcf
```

В окне: **R** — рамка, **C** — клик, **Q** — выход.

Актуальные флаги: `--tracker`, `--verify-threshold` (порог NCC), `--lost-patience`,
`--reacquire` / `--reacquire-threshold` / `--reacquire-radius` /
`--reacquire-scale-min/max` / `--reacquire-interval`, `--roi-smooth`, `--lock-size`.
Часть старых флагов (`--min-iou`, `--verify-rel`, …) принимается для совместимости CLI,
но в новом алгоритме почти не влияет.

```python
from object_tracker import ObjectTracker

trk = ObjectTracker(kind="kcf")
trk.init(frame_bgr, (x, y, w, h))
ok, roi = trk.update(next_frame)
```

В `video_track_depth.py` тот же класс; `--track-only` — только трекинг без SGBM.

## Использование

Базовый запуск:

```bash
python depth_map.py --left left.png --right right.png --output disparity.png
```

Или одно **SBS-фото** (side-by-side: левая/правая половины кадра):

```bash
python depth_map.py --sbs stereo_sbs.png --calib stereo_calib.npz --wls --show
```

С WLS-фильтром (сглаживание, заполнение пропусков) и просмотром результата:

```bash
python depth_map.py -l left.png -r right.png --method sgbm --wls --show
```

Сохранить сырую карту диспаритетов для дальнейших расчётов:

```bash
python depth_map.py -l left.png -r right.png --save-raw disparity.npy
```

## Диапазон диспаритета и дистанции 10–30 м

Ближе объект → **больше** диспаритет. Один фиксированный `--num-disparities`
не закрывает широкий диапазон дистанций:
- малое значение (128) — видит ~30 м, но «слепнет» на 10 м;
- большое (512) — видит ближних, но дальние часто пропадают из‑за ложных
  совпадений на огромном диапазоне поиска.

По умолчанию при наличии `--calib` включён `--auto-disparity`: диапазон
считается из `--z-near`/`--z-far` (метры). Если диапазон широкий, включается
двухполосный SGBM (`--fuse-disparity`) — отдельно ближняя и дальняя полосы,
затем склейка.

```bash
python depth_map.py --sbs scene.png --calib stereo_calib.npz ^
    --z-near 8 --z-far 40 --wls --show
```

Чтобы задать диапазон вручную, как раньше: `--no-auto-disparity --num-disparities 256`.

## Измерение расстояния до объекта

Расстояние вычисляется по диспаритету двумя способами:

- **С калибровкой** — через матрицу `Q` (результат в единицах `--square-size`,
  обычно мм):

```bash
python depth_map.py -l left.png -r right.png --calib stereo_calib.npz \
    --measure 320 240
```

- **Без калибровки** — по формуле `depth = focal · baseline / disparity`,
  если известны фокусное расстояние (в пикселях) и база камер (в мм):

```bash
python depth_map.py -l left.png -r right.png --focal 700 --baseline 60 \
    --measure 105 105 --measure 275 165
```

Диспаритет усредняется (медиана) по окну `--measure-window` вокруг точки,
чтобы снизить влияние шума. Отмеченные точки и подписи с расстоянием
сохраняются на выходной карте. В режиме `--show` можно **кликать мышью**
по карте диспаритета — расстояние в точке печатается и подписывается сразу.

## Калибровка и ректификация камер

Если снимки сделаны обычной (некалиброванной) стереопарой, изображения
нужно сначала **откалибровать и ректифицировать**. Для этого снимите
10–20 пар кадров шахматной доски с разных ракурсов обеими камерами.

Понадобится распечатанный шахматный паттерн (например 9×6 внутренних
углов). Печатайте в масштабе 100% и после печати проверьте размер клетки
линейкой — это значение и укажите в `--square-size`.

1. Выполните стереокалибровку по **отдельным** кадрам:

```bash
python calibrate_stereo.py --left "calib/left_*.png" --right "calib/right_*.png" --cols 9 --rows 6 --square-size 25 --output stereo_calib.npz
```

Или по **SBS-фото** шахматной доски (то же разрешение половин, что потом в depth/video):

```bash
python calibrate_stereo.py --sbs "calib/sbs_*.png" --cols 9 --rows 6 --square-size 25 --output stereo_calib.npz
```

Если левая камера оказалась справа в кадре — добавьте `--swap-lr`.

Здесь `--cols`/`--rows` — число **внутренних** углов доски, `--square-size` —
размер клетки в мм. Для сцен без дисторсии (Blender / узкий объектив) полезно
зафиксировать лишние коэффициенты:

```bash
python calibrate_stereo.py --left "..." --right "..." --square-size 90 --fix-k3 -o stereo_calib.npz
# или идеальный pinhole:
python calibrate_stereo.py ... --zero-distortion
```

Флаги: `--fix-k1`, `--fix-k2`, `--fix-k3`, `--fix-tangential` (p1,p2), `--zero-distortion`.

Можно сначала откалибровать камеры по отдельности, а стереопару — уже
с фиксированными интринсиками (`CALIB_FIX_INTRINSIC`):

```bash
python calibrate_stereo.py --mono left  --images "calib/left_*.png"  --cols 9 --rows 6 --square-size 25 -o left_intrinsics.npz
python calibrate_stereo.py --mono right --images "calib/right_*.png" --cols 9 --rows 6 --square-size 25 -o right_intrinsics.npz
python calibrate_stereo.py --left "calib/left_*.png" --right "calib/right_*.png" \
  --calib-left left_intrinsics.npz --calib-right right_intrinsics.npz \
  --cols 9 --rows 6 --square-size 25 -o stereo_calib.npz
```

После полной стереокалибровки mono-файлы можно сохранить через
`--export-mono-left` / `--export-mono-right`.

Программа выведет RMS-ошибку
(хорошо < 1 пикселя), рассчитанные `focal` и `baseline`, и сохранит все
параметры (`Q`, карты ремаппинга, `focal_px`, `baseline_mm` и т.д.).

Параметр `--alpha` (0..1) управляет обрезкой при ректификации:
- `1` (по умолчанию) — сохраняется весь кадр, по краям могут появиться чёрные поля;
- `0` — обрезка до общей валидной области, без чёрных полей, но заметно «уже» кадр.

После калибровки программа выводит проверку качества (RMS, база, % валидных
пикселей) и предупреждения, если калибровка подозрительная. Те же
предупреждения показываются в `depth_map.py` и веб-интерфейсе при загрузке
`.npz`.

Если после ректификации изображение кажется сильно обрезанным, пересоздайте
калибровку с `--alpha 1` (или промежуточным значением, например `0.5`).

2. Постройте карту глубины с ректификацией и получите глубину/облако точек:

```bash
python depth_map.py -l left.png -r right.png --calib stereo_calib.npz \
    --wls --depth depth.npy --point-cloud cloud.ply -o disparity.png
```

То же для SBS-снимка:

```bash
python depth_map.py --sbs scene_sbs.png --calib stereo_calib.npz \
    --wls --depth depth.npy --point-cloud cloud.ply -o disparity.png
```

Файл `cloud.ply` можно открыть в MeshLab, CloudCompare или Blender.

## Live-запись и трекинг (`video_record.py`)

PySide6-приложение для UDP-камер П139: превью, сырая запись left/right MP4
и опционально live-трекинг с дистанцией по стереокалибровке.

```bash
python video_record.py
```

1. Дождитесь двух камер в таблице, выберите обе и запустите потоки.
2. Назначьте роли **Left / Right** (кнопка смены ролей меняет местами).
3. В блоке «Трекинг / дистанция» укажите `stereo_calib.npz` → **Загрузить**.
4. Включите «Трекинг + дистанцию», выберите объект (**ROI рамкой** или **кликом**).
5. На превью слева — оверлей (рамка, дистанция, диапазон диспаритета); справа — сырой кадр.
6. «Начать запись MP4» пишет сырые `P139_left_*.mp4` / `P139_right_*.mp4` без оверлея.
   С флагом «Писать аннотированное видео» дополнительно создаётся
   `P139_annotated_*.mp4` (левый кадр с оверлеем).

Без калибровки можно включить только трекинг (без дистанции) — программа спросит
подтверждение. Логика пайплайна вынесена в `stereo_live.py`
(`LiveTrackDepthController`), переиспользует `video_track_depth` / `object_tracker` /
`depth_map`.

## Важно

- Изображения стереопары должны быть **ректифицированы** (выровнены по
  горизонтали): соответствующие точки лежат на одной строке. Если
  снимки не выровнены, используйте `calibrate_stereo.py` и передайте
  результат в `--calib` (см. раздел «Калибровка и ректификация камер»).
- Файл калибровки строится под конкретное разрешение камер — стереопара
  для `depth_map.py --calib` должна иметь то же разрешение, что и кадры
  доски при калибровке.
- Чем ближе объект, тем больше диспаритет и тем "теплее" (ближе к
  красному в палитре JET) он отображается.
- Для перевода диспаритета в реальную глубину нужна фокусное расстояние
  `f` и база `B`: `depth = f * B / disparity`.

## Как это работает

1. Изображения загружаются в градациях серого.
2. Алгоритм сопоставления ищет для каждого пикселя левого изображения
   соответствующий пиксель в правом и вычисляет смещение (диспаритет).
3. При включённом WLS-фильтре строится дополнительная карта справа-налево,
   и результат сглаживается с учётом границ исходного изображения.
4. Карта диспаритетов нормализуется и раскрашивается выбранной палитрой.
